# Settings, for 1.1

> Written 2026-09-13 against the shipped 1.0 settings, from a read of `SettingsActivity.kt` and the
> strings it draws. Nothing here is implemented. The complaint it answers: there is too much text to
> read, the fine detail is in the way of the ordinary controls, a colour is typed as `#FF1B1B1B`,
> and the whole thing is badly set.

## 1. What is actually wrong

It is not the prose. Of 357 strings, 328 are under sixty characters; the only long ones are the
permission disclosures, which are a promise the app makes and are not being trimmed. The text comes
from the **shape of the rows**, and there are four separate faults.

**Every row is two lines.** `RowAdapter` draws a label and a detail beneath it over the platform's
`simple_list_item_2`. A screen of twelve settings is twenty-four lines of prose stacked vertically,
and nothing about the second line is scannable — it is a sentence where a value belongs.

**Values are spelled out.** A colour is `#FF1B1B1B`. An alignment is the word "Centre". A badge
style is the word "Circle". A size is "24". The one thing a person wants to see — what it looks
like — is the one thing the row does not show.

**Nothing is tiered.** Eleven entries on the menu, and behind them flat lists that mix "which apps
are on my home screen" with "badge height as a fraction of the row's text size". The worst two:

| Screen | Rows | Of which |
|---|---|---|
| Gestures | 18 | 10 gestures, then 4 info lines × tap and long press, each with a detail line |
| Theme editor | ~30 | 11 colours typed as hex, 9 sizes and paddings, 5 section headers |

**It is set badly.** The title has a 20dp gutter, the list rows have the platform's, and the prose
pages have their own — three different left edges down one screen. Headers are uppercase 13sp with
no space above them. Checkmarks, radio buttons and plain rows sit in one list with no grouping
beyond a header, and the platform layouts put their own padding inside atomic's.

## 2. Three rules

**A value is shown, not spelled.** A colour is a swatch. An alignment is three short lines drawn
left, centre or right. A badge style is a `BadgeDrawable` at the row's own text size — the class
already exists and already draws it. A size is a number and a slider. On and off is a check and
nothing else. Every value that becomes a picture removes a line of text from the screen.

**One screen, one job; the rest behind `Advanced`.** Each screen keeps the controls someone opened
it for — no more than seven — and ends with a single `Advanced` row holding everything else.
Nothing is removed and nothing is buried two levels deep; the detail is one tap away, on a screen
where it is the subject rather than the noise.

**One grid.** A 20dp gutter for everything: title, rows, prose, dialogs. Rows are 56dp with the
label at 17sp on the left and the value right-aligned in the secondary colour on the same line.
Headers are 13sp, tracked, with 24dp above and 8dp below. Section spacing does the grouping, so
there are still no dividers.

## 3. What goes where

Everyday on the left, `Advanced` on the right. Where a screen is already short it keeps everything.

| Screen | Everyday | Advanced |
|---|---|---|
| Home apps | the list, add and remove, rename, hide | row gap, minimum row height, fallback count |
| Gestures | four swipes, double tap, long press | four long swipes, the eight info-line bindings |
| Theme | pick one of four, day/night, edit | share, import, reset |
| Theme editor | background, text, accent, one text size | secondary text, night overrides, per-role sizes, padding, row gap, badge geometry |
| Background | mode, pick a wallpaper or a source | interval, wi-fi only, order, dim, scrim, fallback colour |
| Info lines | which of the four show | each line's format string |
| Badges | on/off, per-app | include ongoing, style, position, scale, colours |
| System | the six actions, each with its grant | device-admin lock, restricted-mode help |

The Gestures screen keeps its eighteen surfaces but stops reading as a wall: four swipes under one
header, the rest under `Advanced`, each row one line with its bound action right-aligned, and an
unbound surface dimmed rather than spelling out "Nothing".

## 4. The colour picker

A colour is currently an `EditText` and `ColorValue.normalize`. What replaces it, in one dialog:

- **The colour, large**, across the top, over a chequerboard so alpha is visible.
- **Swatches**: the theme's own four, the four built-in themes' palettes, a grey ramp, and — on
  Android 12 and up — the Material You tokens, which are values this app already accepts
  (`@android:color/system_accent1_200`). `auto` sits here too, as a chip, for the roles that take
  it. Tapping a swatch is the whole interaction for most people.
- **Three sliders** — hue, saturation, value — plus alpha where the role allows it. Each
  `SeekBar` gets a `GradientDrawable` track that shows what it does. Hue is the only one that needs
  a multi-stop gradient; the rest are two-stop and recomputed as the others move.
- **The hex field** stays, at the bottom, for the people who have a palette already.

No dependency: `SeekBar`, `GradientDrawable`, `Color.HSVToColor` and the existing normalizer. Own
file, `settings/ColourPicker.kt`, because `SettingsActivity` is already 1964 lines. Everything it
can produce is a value the theme schema already stores, so no document change and no migration.

## 5. Row formatting

One custom row view replaces the three platform layouts, because the platform's padding is what
fights the 20dp gutter:

```
┌─ 20dp ─┬───────────────────────────────────────┬── value ──┬─ 20dp ─┐
│        │ Label                            17sp │  ●  / 24  │        │  56dp
└────────┴───────────────────────────────────────┴───────────┴────────┘
```

- Label 17sp, one line, ellipsised at the end; the value never wraps the label.
- Value right-aligned, secondary colour, 15sp — or a 20dp swatch, or a drawn glyph, or a check.
- A second line only where a row genuinely needs a sentence (a grant, a warning), never for a value.
- Disabled rows keep the 0.6 alpha fixed in 1.0 and gain a reason on tap, as now.
- Every non-text value carries a `contentDescription`, so a swatch says "Background, dark grey" to
  TalkBack rather than nothing at all.

## 6. The theme list

Four themes, each currently a name and a sentence. Each becomes one row: the name **set in that
theme's own font**, two swatches showing its background and text, and nothing else. The sentence
moves into the theme file's `description`, where it is already stored, and shows on the detail
screen you reach by tapping.

## 7. What it costs

**The harnesses.** All eight acceptance scripts drive settings by tapping visible text
(`tap_text "Home apps"`). Moving a row behind `Advanced` adds a tap; turning a value into a swatch
removes the text an assertion reads. Every one of `verify-settings`, `-gestures`, `-badges`,
`-background`, `-themes`, `-system` needs its path updated, and that work is part of the change,
not after it.

**The document schema: nothing.** This is all presentation. Settings and themes keep their shape, so
backup files and `.atomictheme` files from 1.0 keep working, and no `minAppVersion` moves.

**Code.** Roughly: a row view and adapter rewrite (~200 lines, deletes the platform-layout branch),
the colour picker (~250, new file), the advanced split (~150 across screens), value drawables for
alignment and badges (~80). `ThemeEditorScreen` moves to its own file on the way past.

**Size.** All of it is drawn, so the APK moves by a few hundred bytes against 2.1 MiB of headroom.

## 8. Order

1. **The grid and the row.** One row view, one gutter, header spacing. Nothing moves yet, so the
   harnesses still pass — this is the change that makes the screens look deliberate.
2. **Values as pictures.** Swatches, alignment glyphs, badge previews, checks without sentences.
3. **The colour picker.** On its own, behind the same rows.
4. **The advanced split**, and the gesture grouping, with the harness paths updated in the same
   commits that move the rows.
5. **The theme list.**
6. **Acceptance** on API 26 and 36, a note in `docs/verification/`, then `versionCode = 10100`,
   `versionName = "1.1.0"`, tag `v1.1.0`.

Phase 1 alone answers "the formatting is bad". Phases 2 and 3 answer "it is all text". Phase 4
answers "normal users are overwhelmed". They are worth doing in that order because each is visible
on its own, and because only phase 4 breaks the harnesses.

## 9. Not doing

Compose, RecyclerView, a preferences library, a settings search, icons beside every row, dividers,
cards, or a redesign of the grant screens — those are long on purpose and stay that way.
